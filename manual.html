UI FORGE MANUAL

「見る → 選ぶ → コピー → 使う」
を迷わず進める。

UI Forgeは、アニメーション付きReact UIを自分のGitHub資産として育てるためのコンポーネント倉庫です。このマニュアルは、CLIやReactに詳しくなくても構造が追えるように説明します。

Current: 30 components · GitHub Registry · PWA
01 · START

まず知る：UI Forgeは何をするもの？

普通の「UI素材サイト」は、見本を見て終わるか、外部ライブラリを依存関係として導入します。UI Forgeは違い、選んだ部品のソースコードを自分のプロジェクトへコピーして所有する方式です。

プレビュー→Open→Copy CLI→自分のアプリへ追加
重要：UI Forge本体は「部品を保管・探す場所」。実際に使うアプリへは必要な部品だけを追加します。
02 · BROWSE

部品を見る

  1. トップの Browse components を押す。
  2. 検索欄で名前・用途・タグを検索する。
  3. カテゴリボタンで Cards / Actions / Navigation / Gamification などに絞る。
  4. 気になるカードの Open を押す。

Open後の3タブ

Install

shadcn CLIで追加するコマンド。

Code

実際のReact / TypeScriptソース。

AI metadata

AIが用途を判断するためのタグ情報。

03 · AI FINDER

用途から部品を探す

名前を知らなくても大丈夫です。たとえば「小学生向け学習アプリ。終わった瞬間に褒めたい」と書くと、完了・学習・子ども・達成などのmetadataを使って相性のよい部品を順位付けします。

入力例スマホの学習アプリで、7日連続を嬉しく見せたい候補Streak Counter / Achievement Toast / Success Burst

現在のFinderはAPI不要のローカル検索です。入力内容は外部AIへ送信されません。

04 · INSTALL

CLIでアプリへ追加する

CLIは、文字でコンピューターに作業を頼む方法です。UI Forgeでは次の1行で、選んだReact部品をプロジェクトへコピーできます。

npx shadcn@latest add branzfamily01/ui-forge-registry/spotlight-card

この1行を分解すると

部分意味
npx必要なツールをその場で実行する仕組み
shadcn@latest最新のshadcn CLI
add部品を追加する命令
branzfamily01/ui-forge-registry部品の保管場所
spotlight-card追加したい部品名
前提：このコマンドはReact / Next.js等の開発プロジェクトのターミナルで実行します。HTML単体のアプリへそのまま貼るコマンドではありません。
05 · SETTINGS

設定画面

右上の ⚙ から開きます。

  • マニュアル：このHTMLを開く。
  • GitHub名：CLI表示に使うowner名。端末内に保存。
  • テーマ：Dark / Light。
  • GitHub Registry：正本リポジトリへ移動。
  • ローカル設定リセット：テーマとGitHub名だけ初期化。GitHubのコードは消えません。
06 · AI CODING

ChatGPT / Claudeから使う

AIに「UI Forgeの○○を使って」と伝えると、部品名を固定できるため、曖昧なデザイン指示より再現しやすくなります。

UI Forgeの success-burst と xp-counter を使って、
学習問題の完了画面を作って。
モバイル優先。完了直後に短く褒めて、XP増加を見せる。

AIがGitHubを読める環境なら、リポジトリや agents/AGENTS.md、llms.txt も参照させられます。

07 · GROW

部品を増やす

UI Forgeは増やす前提です。基本は次の4点セットです。

  1. registry/components/部品名.tsx にソースを追加。
  2. registry.json にshadcn Registry項目を追加。
  3. metadata/components.json に用途タグを追加。
  4. npm run catalog → npm run check。
設計原則：1部品＝1つの良い体験。万能コンポーネントにしすぎず、組み合わせてBlockを作ります。
08 · FILES

ファイル構成

ui-forge-registry/
├─ index.html                 ← 公開トップ
├─ manual.html                ← このマニュアル
├─ registry.json              ← shadcnが読む目録
├─ metadata/components.json   ← AIが読む用途情報
├─ registry/components/       ← React部品の正本
├─ assets/components-data.js  ← ギャラリー表示用データ
├─ agents/AGENTS.md           ← AI向け設計ルール
├─ llms.txt                   ← AI向け案内
├─ manifest.json              ← PWA
└─ service-worker.js          ← オフラインキャッシュ
09 · PUBLISH

GitHub PagesとPWA

公開起点はリポジトリ直下の index.html。GitHub Pagesを main / root にするとそのまま公開できます。

https://branzfamily01.github.io/ui-forge-registry/

PWA対応なので、iPhoneではSafariの共有メニューから「ホーム画面に追加」してアプリ風に開けます。Service Workerはトップ・マニュアル・主要assetsをキャッシュします。

10 · TROUBLE

困ったとき

部品が一覧に出ない

metadata/components.json と registry.json の両方に同じnameがあるか確認し、npm run catalog を実行します。

Copy CLIはできるが追加できない

対象プロジェクトがReact系か、shadcnが利用できる状態か、部品の依存関係（主にframer-motion）が解決できるか確認します。

GitHub Pagesで更新が見えない

ブラウザキャッシュまたはService Workerの旧キャッシュが残ることがあります。再読込、またはホーム画面版を一度閉じて開き直します。

設定を消したい

右上⚙ →「ローカル設定をリセット」。GitHubリポジトリには影響しません。
